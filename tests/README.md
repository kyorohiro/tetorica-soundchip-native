# Standalone release verification

The Python checker uses only the standard library. Native compilation needs CMake 3.20+ and a C++14 compiler. The JavaScript reference smoke, included in a normal verification run, needs Node.js 22+. The optional WASM rebuild needs an installed Emscripten toolchain; the WASM ABI smoke alone works with Node.js 18.3+.

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 tests/check_standalone_release.py \
  --source-zip releases/tetorica-soundchip-native-0.1.0-sources.zip \
  --wasm-zip releases/tetorica-soundchip-native-0.1.0-wasm.zip \
  --work-dir build/standalone-check \
  --build-wasm ym2612
```

The work directory must be empty. Its source tree is extracted from the ZIP, not copied from another checkout. Manifest inventories, hashes, source/license references, Native provenance, all 22 public chips, all 27 WASM recipes and both JavaScript references are checked before building. MSM5205 and OKIM6295 are a separate JavaScript-only set: their entry points and source hashes must be present, their metadata must agree in both catalogs, and their Native/WASM status must remain `not-ported`. CMake File API and compiler-command paths reject outside project sources/includes. Downloading build recipes, external CMake fetches, archive symlinks and escaping paths are rejected. This is not an operating-system network sandbox; installed compiler/system headers and Emscripten's toolchain cache remain toolchain dependencies.

The standalone Native libraries cover YM2612/ymfm, YM2151/ymfm, YM2413/ymfm, YM2203/ymfm, YM2608/ymfm, YM2610/YM2610B/ymfm, Sega PSG, AY-3-8910, OKIM6258 and RF5C164: eleven chip IDs in ten libraries. Normal verification builds all ten static libraries and runs `tetorica.ym2612.self_test`, `tetorica.ym2151.self_test`, `tetorica.ym2413.self_test`, `tetorica.ym2203.self_test`, `tetorica.ym2608.self_test`, `tetorica.ym2610.self_test`, `tetorica.segapsg.self_test`, `tetorica.ay8910.self_test`, `tetorica.okim6258.self_test` and `tetorica.rf5c164.self_test` through CTest, with assertions enabled in Release builds. The YM2151 fixture covers eight FM channels, pan, timers/status/IRQ, separate FM/CSM cancellation, Stop/reset and non-advancing observations, with allocation/free checks on the tested rendering paths. It does not instantiate X68000's OKIM6258 core. The independent PSG fixture covers three tone channels, noise, stereo, mute, clock edits, retained Stop/reset and observation without an OPLL or Genesis FM core. The YM2413 fixture covers nine melodic channels, built-in/user instruments, five rhythm aliases with physical-channel sharing, Stop/reset, cancellation, observation and deferred audition. The independent AY fixture covers three tones, shared noise/envelope, clock changes, synchronous readback, retained levels, Stop/reset and audition without allocating an OPLL sibling. The YM2203 fixture covers three FM plus three SSG voices, shared noise/envelope, prescalers, source/channel mutes, timers/status/IRQ, retained controls, separate FM/CSM cancellation and observation, including the primary/additional reset-history distinction. The YM2608 fixture checks FM/SSG/rhythm/ADPCM-B controls, fixed memory boundaries/copies/retention, raw CPU memory transfers, timers/status/IRQ, cancellation, observational snapshots and both constructor profiles. The shared YM2610 fixture checks both FM variants and both profiles, A/B dense ROM boundaries/copies, sparse-page ownership, retained memory/controls, Stop/reset, cancellation and observational status/state. The independent OKIM6258 fixture checks borrowed sample lifetime/replacement, low-nibble/FIFO continuity, clock/divider guards, pan, repeat, retained Stop/reset and non-advancing observation. The RF5C164 fixture checks both profiles, copied/banked RAM, markers, eight voices, clocks, reset/clear, ordinary mask-held timing and extra immediate cancellation/foreign-voice isolation.

The checker also enables `TETORICA_NATIVE_BUILD_EXAMPLES`, requires `tetorica_genesis_wav`, `tetorica_master_system_wav`, `tetorica_msx_wav`, `tetorica_pc98_ym2203_wav`, `tetorica_pc98_ym2608_wav`, `tetorica_neogeo_wav`, `tetorica_x68000_wav` and `tetorica_megacd_wav`, and runs all eight with selected output paths containing spaces. It checks each file's RIFF structure, 48 kHz stereo PCM16 format, complete frame count of at least one second, and nonzero, unclipped output on both channels. Each example produces 144,000 frames, links real chip libraries and generates its own notes/percussion. The MSX host combines AY and OPLL; the PC-98 hosts use YM2203 FM/SSG and YM2608 FM/SSG/rhythm/ADPCM-B, respectively. The NeoGeo host uses all four YM2610 physical FM slots, SSG and ADPCM-A/B. The X68000 host combines a separate YM2151 and OKIM6258, keeping its borrowed synthetic ADPCM buffer alive beyond the decoder. The Mega-CD host combines YM2612, Sega PSG and primary RF5C164 with a copied looping PCM waveform. The sample examples generate original data rather than loading hardware/game ROM contents. No audio device or external sample assets are used. Fixed example mix gains do not alter library defaults or model motherboard analog mixing.

The released WASM artifact and Node ABI smoke remain YM2612/ymfm only. Other chips retain source recipes and their explicitly recorded verification/license status. The Node smoke tests synchronous reads, audible finite stereo output, reset and exact PCM continuation after save/load. It loads the supplied loader unchanged through a temporary `.mjs` file, with explicit WASM bytes and no npm dependencies.

The checker selects Release explicitly for single- and multi-configuration CMake generators. It requires all ten Native fixtures and eight WAV example artifacts in CMake's File API, supports Windows `.exe` paths and spaces, and audits relative compiler paths and MSVC include options. `--work-dir` may be absolute or relative to the invocation directory. The directory must be empty.

The [CI workflow](../.github/workflows/verify-sdk.yml) is configured to run all ten Native fixtures, eight WAV examples and the JavaScript verification on Windows, Linux, and macOS, including Linux ARM64 and both Mac architectures. A separate Ubuntu job builds and audits the YM2612 WASM release and repeats the WASM build/smoke using its extracted source ZIP. Completed runs and their exact target scope are recorded in [verification.md](../docs/verification.md).

The JavaScript smoke imports the copied engines from the extracted source tree and checks audible finite stereo output, exact chunk continuity, mute progression, reset, MSM5205 external VCLK, OKIM6295 sample/voice commands, stop/end behavior and attachment gain. It also runs the synthetic rendering example from a temporary directory and verifies both PCM16 WAV files. No npm installation, browser or audio device is used.

To recheck unchanged releases without compiling again, pass `--audit-only --wasm-smoke --javascript-smoke`. With just `--audit-only`, no compiler or Node process is started. To run either smoke directly:

```sh
node tests/wasm_smoke.mjs /path/to/extracted-release/wasm
node tests/javascript_reference_smoke.mjs /path/to/extracted-source/reference/javascript
```
